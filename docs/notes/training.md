## 2026-10-08 切り分けの決めごと（`scripts/prepare.py`）

- 縮小しない。分裂像は 50px 四方しかない。原寸で 640px に切り、imgsz も 640
- 区分は 2 つ（0 = 分裂像、1 = 似た別物）。似た別物を別の区分として覚えさせ、成績は 0 で見る
- val は配布元の train から標本単位で 15%（腫瘍ごと、seed 0）。古典籍で「ページ単位の分割は甘い」と
  分かったので、最初から標本単位にした
- 何も写っていない切片: train では 1 割だけ残す。val・test は全部残す（標本全体の誤検出を測るため）
- 切片の境目で割れた枠は、半分以上入っている側に残す。ちょうど半分ずつなら両方に入る。
  最後の切片は端にそろえるので前の切片と重なり、そこの枠は 2 回数えられる
  （006 の試しで、元の 36 枠が切片の上で 38 枠になった）
- 元の TIFF は切ったら消す（65GB をディスクに置かない）

途中で分かったこと:

- figshare の API を 500 件続けて引くと 403 で止められる（8 並列でも、1 件ずつ 0.3 秒空けても）。
  ファイル ID は配布元の `Setup.ipynb` の辞書から取り、画像は `ndownloader.figshare.com/files/<ID>` から
  直接取るようにした。API は使わない
- `MIDOG++.json` には 553 枚が載っているが、画像が配られているのは 503 枚。151〜200（乳がん 50 枚）は
  画像が無い。分割の CSV にも載っていないので、そのまま除いた
- 手元で各分割 1 標本を切って、枠を描いて目で確かめた。枠は濃く染まった核に乗っていて、ずれは無い
- mdx-gpu のディスクは 199GB 中 102GB 空き（前回の 97% から片付いていた）。環境は ndl-layout と同じ
  `~/venv`（torch 2.13.0+cu130、Ultralytics 8.4.119）

## 2026-10-10 配布元の評価の仕方（中心が 7.5µm 以内、F1）で測った

`scripts/eval_points.py <best.pt>`。結果は mdx-gpu の `runs/<モデル>-midog/test_points.json`
（切片ごとの予測を標本の座標に戻したものを `points_{val,test}.json` に取ってある）。

配布元のコード（DeepMicroscopy/MIDOGpp の `evaluation.py`、突き合わせは evalutils 0.4.2 の `score_detection`）を
読んで合わせたこと:

- 正解は区分「分裂像」の中心の点。予測も分裂像の区分だけを使う（似た別物の予測は捨てる）
- 座標を µm に直し、中心どうしが 7.5µm 以内なら当たり。正解の順に、いちばん近いまだ使っていない予測を当てる（貪欲法）
- F1 は 111 標本の TP・FP・FN を**足してから**出す（配布元の aggregate）。腫瘍の種類ごとも同じ
- しきい値は val（5,652 切片、70 標本）で F1 が最大になる値を選び、test に当てた

配布元と違うこと:

- 配布元は標本を丸ごと推論する。ここは切り分け済みの 640px 切片で推論し、標本の座標に戻した。
  切片の重なりでできた二重の予測は、配布元の後処理と同じ距離の NMS（半径 25px）で 1 つにした
- しきい値を探す範囲を 0.05〜0.95 にした（配布元は 0.50〜0.99。自分たちの検出器の出力に合わせた範囲）

途中で分かったこと:

- **画素の大きさはスキャナで違う。** TIFF の解像度タグを見ると 0.2263〜0.2533µm/px の 9 通り
  （val・test の 170 標本）。7.5µm は 30〜33px にあたる。配布元はこのタグで mm に直して比べている
- 元の TIFF は消してあったので、figshare から**先頭と IFD の所だけ**を Range で取ってタグを読んだ
  （`data/spacing.json`）。figshare は S3 へ転送するので、転送先の URL を覚えて使い回さないと 1 標本 30〜60 秒かかる
- 確信度 0.01 で推論すると、batch 32 では 11x・26x が GPU のメモリ（40GB）を使い切った。batch 16 で通った
- test の分裂像の正解は 2,467 個（どのモデルも TP+FN = 2,467 で、数が合う）

| モデル | しきい値（val） | val F1 | 適合率 | 再現率 | **test F1** | TP / FP / FN | 標本ごとの F1 の平均 |
|---|---|---|---|---|---|---|---|
| yolov8x | 0.38 | 0.817 | 0.788 | 0.831 | **0.808** | 2,049 / 553 / 418 | 0.706 |
| yolo11x | 0.40 | 0.826 | 0.760 | 0.851 | **0.803** | 2,100 / 662 / 367 | 0.713 |
| yolo26x | 0.39 | 0.824 | 0.783 | 0.825 | **0.803** | 2,034 / 565 / 433 | 0.701 |

腫瘍の種類ごとの test F1（括弧は正解の数）:

| 腫瘍 | yolov8x | yolo11x | yolo26x |
|---|---|---|---|
| 犬 肥満細胞腫（491） | 0.900 | 0.885 | 0.882 |
| 犬 リンパ腫（840） | 0.828 | 0.824 | 0.819 |
| 人 黒色腫（220） | 0.841 | 0.824 | 0.814 |
| 人 乳がん（339） | 0.784 | 0.780 | 0.767 |
| 犬 軟部肉腫（248） | 0.741 | 0.733 | 0.762 |
| 犬 肺がん（214） | 0.697 | 0.727 | 0.702 |

- **mAP50 では 11x が一番だったが、F1 では v8x が一番になった。** ただし差は 0.005 で、順位は意味を持たない
  （seed の揺れを測っていない）。3 モデルとも F1 0.80〜0.81
- しきい値は 3 モデルとも 0.38〜0.40 にそろった。test で最良のしきい値（参考、選んではいけない値）にすると
  11x 0.816・26x 0.809・v8x 0.808。val で選んでも損は 0.013 以内
- 腫瘍の種類で差が大きい（0.65〜0.90）。数の多い肥満細胞腫・リンパ腫が高く、神経内分泌腫瘍・肺がんが低い。
  モデルの差より腫瘍の差のほうがずっと大きい
- 標本ごとの F1 の平均（0.70〜0.71）は、足してから出す F1（0.80〜0.81）より低い。分裂像の少ない標本では
  1〜2 個の誤りで F1 が大きく動くため。配布元の数字と比べるときは足してから出すほうを使う

限界: 配布元の論文の基準の値（RetinaNet）とはまだ並べていない（論文の表を確かめてから書く）。
切片で推論しているので、切片の端で切れた分裂像の扱いが配布元と少し違う。

主張の候補: 「配布元の評価（中心が 7.5µm 以内の F1）でも、3 世代の YOLO は test F1 0.80〜0.81 でほぼ同じ。
モデルの差（0.005）より腫瘍の種類の差（0.65〜0.90）のほうがずっと大きい」（根拠は上の 2 つの表）

## 2026-10-09 1 種類を抜いて学習する実験（leave-one-tumor-out）を始めた

ねらい: 学習で見たことのない腫瘍の種類に出会ったとき、成績がどれだけ落ちるか。
上の表の「腫瘍の種類の差（0.65〜0.90）」が、種類そのものの難しさなのか、見慣れなさなのかを分ける。

**配布元の論文が同じ実験を既にしていた。** Aubreville et al. 2023（上記）の Table 6・Fig. 4。
RetinaNet、512px の切片、train を 5 分割した交差検証の平均。しきい値は各分割の val で選んでいる。
2024 年に訂正（Author Correction, Sci Data 11, 717, https://doi.org/10.1038/s41597-024-03548-x）が出ているが、
中身は本文の XML に無く、何が直ったかは確かめていない。

論文の値（F1。「全種類」は Table 4 の all の行、「抜いた」は Table 6 の対角）:

| 腫瘍 | 全種類で学習 | その種類を抜いて学習 |
|---|---|---|
| 人 乳がん | 0.71 | 0.66 |
| 犬 肺がん | 0.68 | 0.63 |
| 犬 リンパ腫 | 0.73 | 0.57 |
| 犬 肥満細胞腫 | 0.82 | 0.77 |
| 人 神経内分泌腫瘍 | 0.59 | 0.59 |
| 犬 軟部肉腫 | 0.69 | 0.65 |
| 人 黒色腫 | 0.81 | 0.79 |

- 落ち方は 0〜0.16。リンパ腫がいちばん落ちる（論文は細胞が小さく見た目が違うためと説明）。神経内分泌腫瘍は落ちない
- ここの v8x（全種類で学習）は 7 種類すべてで論文の「全種類」を上回る（例: 神経内分泌腫瘍 0.645 対 0.59）。
  ただし論文は 5 分割の平均、こちらは 1 回の学習なので、揺れの大きさは揃っていない

決めごと（`scripts/loto.py`・`scripts/loto.sh`）:

- モデルは yolov8x だけ。3 モデルの差は 0.005 しかなく、見たいのは腫瘍の差。v8x は 1 エポックがいちばん速い
- 抜いた種類は train と val の両方から外す。val は最良のエポックとしきい値を選ぶのに使うため
- 切り直さない。切片の名前が標本番号で始まるので、使う切片の一覧（テキスト）を学習に渡す
- seed・batch・imgsz は既存と同じ。patience だけ 50 → 20（既存の v8x は 30 エポック目が最良なので、20 でも同じエポックが選ばれる）
- 測るのは配布元の評価（7.5µm 以内の F1）。test は全種類を推論し、抜いた種類と残した種類の両方を見る

## 2026-10-16 入力の違いの内訳を分けた（標本 345）

`scripts/split_input_diff.py` で、CPU 32 ビット版と Python の確信度の差が 0.03 を超えた 10 点について、
その点を含む切片（12 枚）を Python（best.pt、手元の Mac）で 3 通りの入力から推論し直した（`out/split-input-345.json`）。

- raw: 元の TIFF から切った切片そのもの（JPEG を通さない）
- patch: raw を PIL で JPEG 品質 95 にして読み直したもの（学習・Python の評価と同じ入力）
- tiles: ブラウザと同じ IIIF のタイル（512 角）を PIL で読み、貼り合わせたもの

| 比べたもの | 確信度の差の最大（10 点） |
|---|---|
| ブラウザ（CPU 32 ビット） vs tiles | 0.000 |
| patch vs tiles | 0.469 |
| raw vs patch | 0.287 |
| raw vs tiles | 0.538 |
| 元の Python の結果 vs patch（同じ入力のはず） | 0.062 |

- **ブラウザと Python は、同じタイルを入れれば完全に一致した。** JPEG の読み方（ブラウザと PIL）や推論の実装の違いは効いていない。
  差はすべて入力の画像から来る
- **効いているのは切り方。** 切片は 0, 640, 1280, … と並べ、右端の列と下端の段だけは画像の端にそろえる。
  345（6447 × 4835）では右端が x=5807、下端が y=4195 で、どちらも 16 の倍数でない。
  JPEG は 16 画素の区画ごとに圧縮するので、ここだけ切片とタイルの区画がずれ、画素の差が平均 2.1（0〜255）になる。
  それ以外の切片は 640 も 512 も 16 の倍数なので区画がそろい、画素の差は平均 0.01（最大 9）しかない
- 突き合わせた 333 点全体で見ても同じ傾向:

| 点のある切片 | 点の数 | 差の中央値 | 90% 点 | 最大 | 0.03 超 |
|---|---|---|---|---|---|
| 右端・下端の切片を含む | 68 | 0.0019 | 0.035 | 0.469 | 8 |
| 区画のそろった切片だけ | 265 | 0.0001 | 0.002 | 0.115 | 2 |

- ただし **JPEG そのものでも同じくらい動く**（raw vs patch で最大 0.29）。どちらが「正しい」入力というわけではなく、
  これらの点ではモデルの確信度が、画素の小さな揺れで 0.1〜0.5 動くほど不安定だということ。
  区画のそろった切片でも、画素の差が最大 9 の所で 0.10 動いた点がある（(3584, 956): patch 0.68・tiles 0.78）
- 元の Python の結果と、手元で作り直した patch が 0.06 ずれる理由は確かめていない。元の結果は mdx の GPU で 16 枚ずつ推論した。
  手元は Mac で 1 枚ずつ。PIL の JPEG の版の違いもありうる
- 006 で差が小さかったのは、たぶん分裂像が少なく、右端・下端の切片に境目の点が無かったため（確かめていない）

**訂正（10/16 の上の節）:** 「入力の違いだけでも最大 0.18」は、両方がしきい値 0.39 以上の点だけを比べた値だった。
すべての点で比べると最大 0.469 で、(3110, 4772) の Python 0.700・CPU 0.231。この点はしきい値をまたぐ。

次の手（やるかは未定）: 画面での判定を Python とそろえたいなら、右端・下端の切片の左上を 16 の倍数にする（はみ出す分は詰め物をする）。
